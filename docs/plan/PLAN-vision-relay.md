# PLAN-vision-relay：视觉读图两段式（vision 模型直发豁免）

> 状态：已实施（2026-11-19，待部署） ｜ 日期：2026-11-19 ｜ 适用版本：v1.8.31+ ｜ 立项原话：「要加，而且要逻辑完整：对于已经标注为 vision 的模型，不需要采用两段式处理；对于需要两段式处理的场景，先验证 glm-4.6v-flash 是否免费可用」
> 批准时追加裁定：「池中应该存在其它的免费视觉模型，不一定非得强行使用 glm-4.6v-flash」⇒ 读图器从「单一显式配置」改为**候选链**（见 §2）。

## 0. 前置取证（2026-11-19 现网实测，WSL 网关 1.8.31，zai_api 已存 key）

| 探测 | 读数 | 结论 |
| --- | --- | --- |
| `GET api.z.ai/api/paas/v4/models` | 200，12 ids，无任何 4.6v/4.5v 行 | 免费 SKU 不进上游清单（与 glm-4.7-flash 同型） |
| `glm-4.6v-flash` 文本 ping ×3（间隔 20s） | 429/1305 ×2 → **200**（833ms，usage 真实） | **免费可用成立** |
| `glm-4.6v-flash` 小图问色 ×5（间隔 15s） | 429/1305 ×5，无 200 | **「真收图」未闭环**，阶段 A 复验 |
| 对照 `glm-4.7-flash` 同分钟 ping | 429/1305 | 1305 是账号/平台级拥塞闸，非该模型特有 |
| 对照 `glm-4.6v`（付费 vision） | 429/**1113** Insufficient balance | key 无付费余额，读图器只能免费档 |

1305 特征：亚秒即拒、无 `Retry-After`、措辞 overloaded、重试可穿。既有冷却档位刻意不匹配裸 429（AGENTS.md），本 PLAN 不改那条判据；读图 hop 自带独立的有界退避（见 §2）。

## 1. 语义（用户裁定的完整逻辑）

**触发条件是「这一轮真正服务的模型不能收图」，不是「请求带图」。**

| 场景 | 行为 |
| --- | --- |
| 目标模型已标注 vision=yes（任一层证据） | **直发，零改动**——两段式完全不介入 |
| 具名请求 / pin 指向文本模型 + 请求带图 | 进两段式：读图 hop 把图换成文字，再按原文本目标转发 |
| 路由池有 vision 候选 | **不触发**两段式：现有硬过滤把池裁到 vision 子集，正常服务（保持今天行为） |
| 路由池 vision 候选为空、但池里有文本模型且开关开 | 先试读图 hop；成功 → 画像翻成纯文本、按文本池选路；失败 → 维持今天的 503 `no_available_model` + `missing:['vision']` |
| 开关关（默认） | 一切行为与今天完全相同 |

「已标注为 vision」沿用能力解析链的既有判据（人工 > 上游声明 > 标准库 > probe > 第三方 modalities/vision），**不新造第二套 vision 判定**；`vision-capable` 谓词（`autoRouting.ts:153-168`）就是唯一入口。

## 2. 读图 hop 设计

- **位置**：`autoRouter.select()` 之前、请求画像计算处（`routes/chat.ts` 主链路 + responses/anthropic 泳道共用的归一化之后）。理由：hop 改变的是「请求要不要 vision」这个画像事实，必须在硬过滤之前落定；挂在 doForward 会踩两条源码结构门（tool-adjacency 先例）。
- **读图器选择（2026-11-19 批准时改裁定：候选链，不锁死单一模型）**：
  1. 配置 `visionRelay.reader` 显式指定 → 只用它（用户点名优先，失败不换家）；
  2. 未指定 → 自动候选链：**已启用条目中 vision=yes 且 cost=free 的模型**（聚合条目用 `aggregateCostOf` 同一判据；账号渠道用 worker 目录 `free` 标记 + `supportsImage`），按「官方免费证据 > 目录免费标记」排序，同档保持目录顺序；`included`（套餐内）**不进**免费链——用完套餐就停，不是免费；
  3. 链上逐个试：每个读图器独立 3 次退避；一个彻底失败换下一个；全链失败 → 503 原样。
  阶段 A 盘点（2026-11-19）：现目录免费 vision 仅 `nvidia_nim/moonshotai/kimi-k2.6`、`open_router/openrouter/free` 两行（均 official 证据、已启用在目录）；`zai_api/glm-4.6v-flash` 收录后加入。注意 `openrouter/free` 是元路由（上游随机派模型），转述质量不稳定，排序上排在具名模型之后。读图器必须自身 vision=yes；链为空 → hop 直接失败，不静默用付费模型。
- **输入范围（铁律边界，2026-11-19 实施中修正）**：**全部图片部件都转述（当轮 + 历史 + 工具结果），绝不删除**。原稿「只处理当轮新图」在真实客户端下不成立：Codex/Claude 每轮重发完整历史（含原图），只转述当轮图时文本目标仍收不下历史图，第二轮起必然 503。1.8.29 铁律的本意是「不静默丢图」——转述成自解释文本标记是替换而非丢弃，满足该铁律。**LRU 按 `sha256(图片字节/url + reader + 模板版本)` 缓存转述**：同一张图每轮得到逐字节相同的标记文本，历史前缀字节稳定，prompt cache 可命中（这同时消解了原稿担心的「转述措辞漂移打穿缓存」）。首次遇到多图历史时逐图转述，受总墙钟约束；超预算 → hop 失败走原 503，绝不半转述半原图混发。
- **转述请求**：读图器收到 `[原当轮文本, 图片…]`，指令是固定模板「逐字转录图中文字；描述布局/颜色/对象/数据；不要回答用户问题」。这是网关自造文本 ⇒ 打 `GATEWAY-TEXT: vision-relay-prompt` 并登记台账（`gateway-authored-text.test.ts` 精确集合 + `no-gateway-system-text.test.ts` 扫描面同步）。它进的是**读图器自己的请求**，不写进用户对话主请求。
- **替换形状**：原 image 部件原位换成 `text` 部件，内容带自解释标记 `[Image relayed via <reader>: …]`（对齐压缩标记自解释先例，不含任何行为指令）。主请求其余字节不动。
- **退避与上限**：1305/429 最多 3 次尝试、间隔 5s/15s（读图 hop 独立预算，不占 AIMD 槽、不触发账号惩罚——它是网关内部请求）；hop 墙钟上限 60s；总预算失败 → 原样走 503 路径。**绝不无限重试**（修剂量教训）。
- **缓存**：转述文本按 `sha256(图片字节 + reader + 模板版本)` 做内存 LRU（上限 64 条）——同一张图在同一会话反复出现时不重复读图。转述措辞漂移导致的 prompt cache 失效是已知代价，接受（免费档无缓存计价差）。
- **usage**：读图 hop 的 usage 单独记一行请求日志（providerId=reader，标记 `vision_relay`），**不并入主请求 usage**（不编造原则）；主响应 `X-ModelPort-Vision-Relay: <reader>` 头留痕。
- **流式**：hop 发生在首字节之前，客户端只感知延迟；hop 期间客户端中止 → 立即终结（对齐既有 abort 语义）。

## 3. 配置与 UI

- `appConfig.visionRelay: { enabled: boolean(默认 false), reader?: string, maxImageBytes?: number(默认 8MB) }`。超大图直接 hop 失败（不静默压缩图片）。
- 设置页「上下文管理」区新增开关 + 读图器选择（下拉列出全部 vision=yes 的已启用模型）；i18n 全语言包同步（含缺译门与 parity 门）。
- 模型页/路由页不加新徽章（本期不扩呈现面；日志与响应头已可归因）。

## 5. 已知代价与不做的事

- 信息有损（转述丢像素级细节）——开关默认关，由用户显式选择。
- 免费档拥塞（1305）下 hop 可能 60s 超时 → 503，体验是「慢后失败」而非「快失败」；接受，因为替代项（付费 vision）该 key 余额为 0。
- **不做**：免费链之外的自动换家（显式指定 reader 时失败不换；自动模式只在免费 vision 链内换）；历史图片转述；图片压缩/缩放；把 hop  usage 并入主 usage；默认开启。
- 同步删除保护（zai_api 免费 SKU 被 `/models` 对齐删掉）**不在本 PLAN 范围**，仍是独立未批项——但阶段 A 加回的 4.6v-flash 同样暴露在该风险下，部署后若点同步会一并丢，届时按同法 addModel 恢复。
